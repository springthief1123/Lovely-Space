Claudeの当初プランと直近のデザイン改善を照合した計画に沿って、PR #6のデザインを保持したまま追加実装しています。PR #6〜#10の変更はPR #11でmainへ統合済みです。

## 今回の実装

| 領域 | 実装と検証対象 |
| --- | --- |
| 初回受信 | 待機期限なしをnullで表す。正・負の単調時計で初回pollの前にsleepしない回帰テスト |
| Cookie | CookieManagerを唯一の保存元としてHTTPでも利用。ドメイン・path・有効期限の属性を維持。保存完了を待ち、拒否・例外・タイムアウトは失敗として扱う |
| プリセット | Room v1。プロフィールと待機メッセージのCRUD、トランザクションで既定値を切替。既存のDataStore入力を一度だけ取り込み、全削除後に再生成しない |
| 入力画面 | 既定値を初回入力に適用し、保存した設定も手動選択。入室フォームを取り直しても利用者が選んだ秘密の年齢・空欄を上書きしない |
| 検索への復帰 | 検索から入室してチャットを閉じても、検索のback stack entryと条件・取得済みページを保持。元の一覧から入室した場合は一覧へ戻る |
| 編集復元 | 編集画面の表示と対象の識別子・内容を保存可能な状態にし、画面再生成後も編集中の対象を復元 |
| 検索 | 名前・メッセージ内の複数語AND/OR、除外語、性別、年齢範囲と秘密、地域、公開・利用状況、名前/年齢/経過順。host+room_idで重複排除 |
| 取得範囲 | ジャンルごとの取得済みページ・部屋数を表示。条件はローカル反映し、次ページは手動追加。初回は共通キャッシュを利用し、更新操作だけ強制取得する。ページ失敗の再試行とジャンル切替の取消をテスト |
| CI | coreテスト、APKビルド、Androidユニットテスト、Lint。Robolectricで初回取り込み・既定切替・編集・削除・DB再オープンを確認。生成したRoomスキーマをリポジトリに保存 |

## 次工程の追加実装（未マージ）

- 検索条件の名前付き保存・適用・名前変更・現在の条件による更新・削除。ジャンルと全条件を保存する。
- 同じジャンルへの適用では取得済みページを再利用。異なるジャンルへの適用では通信取消と取得範囲リセットを行い、利用者の検索操作で取得する。
- 保存・更新の確認中の対象と条件を画面再生成後も復元。読取・保存失敗は表示し、入力を保持して再試行できる。
