# 実装引継ぎ状況（2026-10-05）

Claudeの当初プランと直近のデザイン改善を照合した計画に沿って、PR #6のデザインを保持したまま追加実装しています。本書は進捗を示し、未マージの変更とmainを区別します。

## 今回の実装

| 領域 | 実装と検証対象 |
| --- | --- |
| 初回受信 | 待機期限なしをnullで表す。正・負の単調時計で初回pollの前にsleepしない回帰テスト |
| Cookie | CookieManagerを唯一の保存元としてHTTPでも利用。ドメイン・path・有効期限の属性を維持。保存完了を待ち、拒否・例外・タイムアウトは失敗として扱う |
| プリセット | Room v1。プロフィールと待機メッセージのCRUD、トランザクションで既定値を切替。既存のDataStore入力を一度だけ取り込み、全削除後に再生成しない |
| 入力画面 | 既定値を初回入力に適用し、保存した設定も手動選択。入室フォームを取り直しても利用者が選んだ秘密の年齢・空欄を上書きしない |
| 編集復元 | 編集画面の表示と対象の識別子・内容を保存可能な状態にし、画面再生成後も編集中の対象を復元 |
| 検索 | 名前・メッセージ内の複数語AND/OR、除外語、性別、年齢範囲と秘密、地域、公開・利用状況、名前/年齢/経過順。host+room_idで重複排除 |
| 取得範囲 | ジャンルごとの取得済みページ・部屋数を表示。条件はローカル反映し、次ページは手動追加。ページ失敗の再試行とジャンル切替の取消をテスト |
| CI | coreテスト、APKビルド、Androidユニットテスト、Lint。Robolectricで初回取り込み・既定切替・編集・削除・DB再オープンを確認。生成したRoomスキーマをリポジトリに保存 |

## 次の実装順

1. 最新APKの実機確認。Light/Dark、各タブ、プリセット編集と復元、入室・作成への反映、Cookie共有を経た認証からチャットへの復帰を確認する。
2. 検索条件の保存・適用。Roomのスキーマを更新し、v1からの移行で既存プリセットを保持するテストを追加する。
3. 部屋のお気に入り・非表示と解除。恒久的なユーザーIDは未確認のため、人物を追跡している扱いにせず、hostとroom_idで保存した部屋の現在の状態を再確認する。room_idの再利用も調査する。
4. 認証・セッションの対応表と回帰検証。ログイン・年齢認証・ロボット確認の可視操作、通信切断と再接続、閉鎖失敗、プロセス終了を整理する。
5. 通知・背景監視・順番待ち。Androidのサービス制限と本家の操作条件を調べ、停止・期限・取消を表示できる範囲から実装する。
