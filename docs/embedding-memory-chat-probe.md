# オンデバイスAI PoC 第4段階 — モデル解放と通常チャット画面のRAM/CPU計測

> 管理: [Issue #110](https://github.com/springthief1123/Lovely-Space/issues/110) / Draft PRは本実装の作業ブランチ。元のPoC: #105 → #107 → #109。本機能は **debug専用**であり、実際のサイトの取得や通知をAIに接続しない。

## 背景

Galaxy Z Fold5でEmbeddingGemma 2 Text 270MのCPU推論と日本語意味検索を確認済み。100件合成文の全件新規計算は約8.7秒、モデルと文書ベクトル両方を保持すると約166ms、アプリ強制停止・再起動後にディスクベクトル100件を復元した場合は約654ms。これまでの測定ではPSSの観測ピーク約400〜430MiBだったが、**モデルを解放した後にどこまでメモリが減るか**、**通常のチャット画面での同一プロセスのRAM/CPU負荷**が不明だった。

今回の狙いは、利用者が自分の端末で検証ログを安全に取得すること。**AIと実チャットの同時推論を本番へ入れる試験ではない**。PoCをバックグラウンドで推論させず、本番の巡回・通知・チャット通信コードは変更しない。

## UIと2種類の検証

### A. モデル解放後のRAM変化

1. 最新のPRに付属するdebug APKをGalaxy Z Fold5へ導入する。ホーム画面の「AI意味検索検証」を起動する。モデルファイルは同じアプリIDなので通常は既存コピーが使用可能。
2. 「画面内でCPUモデルを一時再利用する」= **ON**、「永続ベクトルキャッシュ」= 任意。まず5件か100件の意味検索を1回実行し、モデルをメモリに保持する。
3. 画面内の「読み込み済みモデルを解放してRAMを測る」を押す。**操作してから3秒間は画面を離れない**。
4. 解放前、直後、250ms、1秒、3秒の5回のPSS、Native PSS、Java/Native heap、プロセスCPU時間、バッテリー温度等を数値ログに記録する。画面にはPSSの前→3秒後、モデル保持が消えたかを表示する。
5. 「読み込み済みモデルを解放する」の従来ボタンや、アプリの背面化でもモデルは解放するが、それらは今回の**明示的な5点計測**とは別。背面化後の状態は次のBで観察する。

**注記：** PSSの差が直後に出ない場合でもモデル解放の失敗とは限らない。ネイティブメモリの回収・Androidのページ解放・GCのタイミングはOS次第。モデル解放確認には`engine_loaded=false`を併せて使う。`engine_loaded=false`はSDK側のオブジェクト参照の解放状態であり、ネイティブメモリ全量が回収された保証ではない。

### B. 通常のLovely Space画面の負荷

1. 「AI意味検索検証」でモデル再利用ONのまま一度意味検索して、モデルを保持した状態にしておく。
2. 「負荷計測を開始して通常のLovely Spaceを開く」を押す。**通常のMainActivityが起動**する。PoC画面が背面に移ると、既存の`onStop`がモデルの解放を要求する。
3. 通常のLovely Space内で、**自分の普段の使い方**（画面移動や、任意で既存のチャットを開くなど）を最大90秒操作する。チャットの入力内容や入室情報を検証のために共有する必要はない。**テストのために余分な巡回や入室を行う必要もない。**
4. 端末のホーム画面等へ移って5秒以上アプリが背面化した場合は計測を自動停止する。90秒でも自動停止する。通常画面から「AI意味検索検証」のアイコンに戻ると計測を停止する。
5. AI検証画面へ戻ったら「メモリログの容量を更新」を押し、CSVに`screen=main`の行があることを確認する。通常画面を開かずに計測を中断した場合、`screen=main`が無いことがある。
6. 「RAM・通常画面の計測CSVを書き出す」で`lovely-ai-memory-lifecycle.csv`を任意の保存先へ書き出す。ログには測定数値と`screen`（poc/main/background/other）だけが含まれ、どの部屋・相手・チャット画面を開いたかは含まれない。
7. 同じ条件で**3回程度**繰り返し、バッテリー温度の変化・画面遷移・端末の操作感を別途観察する。必要であれば「RAM計測ログを削除する」で内部ログを消す（**既に外部へ保存したCSVは別途ユーザーが管理**）。

## 取得するCSVと測定値の解釈

新しいログ`filesDir/ai-poc/poc-memory-lifecycle-v1.csv`は既存の性能`poc-performance.csv`、実行条件`poc-run-modes-v1.csv`、品質`poc-quality-v1.csv`とは別ファイル。**従来のCSV形式・既存データを変更しない**。

| 列 | 意味 |
| --- | --- |
| `utc`, `run_id` | サンプル時刻と**検証操作ごとに生成したランダムなID**。端末個体識別IDではない |
| `phase` | `release_before` / `release_after_0` / `release_after_250ms` / `release_after_1000ms` / `release_after_3000ms` / `coexistence_transition` / `coexistence_sample` |
| `screen` | `poc`、`main`、`background`、`other`の大まかなActivity状態。**開いていたチャットルームは保存しない** |
| `elapsed_ms` | 各測定開始からの経過（wall clock） |
| `engine_loaded` | debug SDKエンジンの保持状態（true/false）。**RAM解放量そのものではない** |
| `pss_kb`, `native_pss_kb`, `dalvik_pss_kb`, `other_pss_kb` | Androidが推定する同一アプリプロセスのPSSと内訳。値はページの共有などで上下する |
| `private_dirty_kb`, `java_heap_kb`, `native_heap_kb` | プロセスのprivate dirty、Java実使用ヒープ、ネイティブヒープの割当量。互いに重なりうるため**単純合算しない** |
| `process_cpu_ms` | 測定開始からのプロセスCPU累積時間。隣り合う行の**差分**をwall clockの差分で割るとコア換算CPU使用率の近似 |
| `battery_percent`, `battery_temperature_c` | Androidのバッテリー残量・電池温度であり、AI単体の消費電力/SoC温度を直接測っていない |
| `thermal_status` | API29+のAndroid Thermal APIの段階値（0=NONE〜6=SHUTDOWN）。℃とは異なる。端末・OSの対応による |

通常画面の計測は最大**90秒／おおむね1秒ごと**。画面背面化後は最大5秒の移行猶予を設けて停止する。メモリ解放時の5点を含み、CSVは2MiBで上限。画面を復帰しても標本数が足りないことがあり、**サンプリング上のピークが真の瞬間ピークとは限らない**。ログ取得自体にも僅かなCPU/PSS負荷がある。

## セキュリティと採否

- SDKやActivityは`app/src/debug`だけ。本番APKへこの診断機能・CSVを含めない。
- **チャット本文、部屋名、メッセージ、相手の識別子、本家Cookie、pwd、HTTPリクエスト、モデルの絶対パスをログへ出さない。** `run_id`は性能CSVのrun_idとは別で、今回の実験内だけをつなぐランダムID。
- メモリ計測のために端末権限・常駐通知・WorkManager・追加通信を要求しない。通常のMainActivityを開いたことにより生じる通信はアプリの従来の通信規則の範囲。
- 通常画面でモデルを**解放した状態の互換性試験**が目的であり、モデルをロードしたまま実チャットへ渡す機能は追加していない。これを「AIと実チャットの同時推論成功」と誤って扱わない。
- 共有するならユーザーが選んだCSVだけ。実機CSVの生データは公開GitHubにコミットしない。Issue #110にまとめた集計値だけ記録する。

**初期状態：新しいモデル解放・通常画面計測のGalaxy Z Fold5での確認は未実施。** CI成功後に実機結果で判断し、モデルの常駐が適切か、本番レーダーへの接続を許可するかはIssue #101で別途検討する。



## Galaxy Z Fold5 第4段階・実機CSV解析（2026-10-11）

利用者から3種類のCSVを受領し、ユニークな`run_id`と行種別を確認した。**以下は公開可能な集約数値のみ**。元CSVの全行、個別の`run_id`、ユーザーが開いたサイト・チャットの内容は公開リポジトリへ保存しない。

環境: Galaxy Z Fold5（CSV機種コードSCG22、Android API 36）、CPU版EmbeddingGemma 2 Text 270M、架空の募集文100件。記録UTC 2026-10-11 05:58:52～06:00:38頃。

### 元データの構成・照合

- 性能CSV `lovely-ai-benchmark (5).csv`: **50行、summary 1行＋sample 49行**。100件すべて新規埋め込み（`cache_hits=0`、`cache_misses=100`）、全体7,959ms、埋め込み7,399ms、モデル初期化278ms、プロセスCPU時間33,706ms（約423.5%コア換算）、PSS標本ピーク**約484.6MiB**。
- 実行条件CSV `lovely-ai-run-modes (5).csv`: **1行**。性能CSVの`run_id`と**完全一致**。`keep_warm=true`、`engine_reused=false`（初回でモデルを保持）、`persist_vectors=true`、ディスクからの復元0件、永続ファイル314,383bytes。今回の永続ONは**新規計算して保存した実行**で、前段階の「再起動後復元成功」とは別実行。
- RAM CSV `lovely-ai-memory-lifecycle (1).csv`: **91行**。モデル解放の5サンプル・1回と、通常画面の共存計測86サンプル・1回（`poc`が1点、`main`が85点）。RAM CSVの`run_id`は各測定用で、性能/実行条件CSVと共通ではなく、**実行時刻の順序と状態**から一連の操作として解釈した。

### A. モデル解放前後のメモリ

| フェーズ | `engine_loaded` | PSS MiB | Native PSS MiB | Native heap MiB |
| --- | --- | ---: | ---: | ---: |
| 解放前 | true | 472.2 | 140.8 | 210.5 |
| 解放直後 | **false** | 367.1 | 139.9 | 34.2 |
| 解放約250ms後 | false | 367.3 | 139.9 | 34.1 |
| 解放約1秒後 | false | 334.5 | 106.8 | 34.2 |
| 解放約3秒後 | false | **334.8** | **106.8** | **34.0** |

- **モデル保持状態はtrue→falseに変化し、3秒後もfalse**。PSSは**472.2→334.8MiB、約137.5MiB／29.1%低下**。解放直後にも約105.1MiB低下を観測した。
- Native heapの**割当量**は210.5→34.0MiB（約176.5MiB低下）、Native PSSは140.8→106.8MiB（約33.9MiB低下）。PSS、Native PSS、Native heapは定義が異なり**低下量を合算しない**。
- 解放後にもPSSは約334.8MiB残り、OSが物理RAMの全領域を即時回収したことや、他アプリへのメモリ影響がゼロになったことを保証しない。GCの強制は行っていない。
- 単一回、5標本の結果。熱・電池への長期影響や繰り返し測定の分散は未確認。

### B. 通常のLovely Space画面での計測（AIモデル非保持）

通常画面のデータは`screen=main`が**85点**（連続した約88.2秒、標本間隔中央値約1.05秒）、全セッションは`poc`1点を含む86点、最終の経過時間は89.286秒。計測中は全86点で`engine_loaded=false`。

| 項目 | 結果 |
| --- | --- |
| 通常画面のPSS・最初→最後 | **260.6→328.9MiB** |
| 通常画面のPSS・中央値／平均 | **297.9／295.3MiB** |
| 通常画面のPSS・観測範囲 | **260.6〜348.9MiB** |
| 通常画面のNative PSS・最初→最後 | **21.7→53.6MiB** |
| 通常画面のJava heap・観測最大 | 約33.6MiB |
| 通常画面のNative heap・観測最大 | 約70.1MiB |
| 通常画面のプロセスCPU時間増分 | **24,002ms／88,198ms**（約**27.2%コア換算平均**） |
| バッテリー残量 | **72%で変化なし**（記録の分解能では変化なし） |
| バッテリー温度・最初→最後 | **31.4→32.6℃** |
| Android Thermal Status | **全点0（NONE）** |

- **通常MainActivityへの画面遷移と、モデル非保持で約88秒間のプロセス負荷サンプリングに成功**。初期と末尾のPSSは増えているが、途中で上下しており、増加量をそのままメモリリークと判定できない。通常の画面遷移・キャッシュ・GC・描画など複数要因が含まれる。
- 約27.2%はプロセスCPU時間/壁時計時間×100のコア1個換算であり、スマートフォン全体のCPU利用率でも**AIのCPU負荷単独でもない**。
- 電池温度は約90秒で+1.2℃となったが、AIのみ・チャットのみの発熱とは結論できない。Thermal Status 0は記録期間のOSによる熱制限状態「NONE」でありCPU温度が0℃という意味ではない。
- **CSVに保存されている画面状態は`main`まで**。利用者が実際にチャット画面を開きメッセージを送受信したか、操作に遅延・フリーズがあったかは、CSVからは確認できない。
- 背景化による自動停止・手動停止・ログ削除ボタンの操作は今回のCSVからは独立に確認できない。90秒近くでログが終わっていることは最大時間制限と整合するが、停止理由のイベントは記録されていない。

### 技術判断と残件

- **確認済み**: モデル解放と3秒以内のプロセスPSS/Native heap減少、通常画面でのAIエンジン非保持・プロセスCPU/PSS観測、デバッグCSV保存・手動エクスポート。
- **暫定的な方針**: Galaxy Z Fold5では「必要時だけモデルをロード→既存の合成文ベクトルを再利用→使用終了時にモデルを解放」が良い候補。前段階の強制停止後キャッシュ100件復元も確認済み。ただし実サイトにデータを適用する許可にはならない。
- **未確認**: RAM測定の反復性、背景移行による解放と記録停止、他アプリのメモリ圧迫時の挙動、通常画面での実際のチャット入出力・操作感、熱/電池の長時間影響、モデル入替/キャッシュ破損からの実機復旧。モデル保持中と実チャットを**同時に**動かす性能は測っていない。
- [Issue #110](https://github.com/springthief1123/Lovely-Space/issues/110) と [Draft PR #111](https://github.com/springthief1123/Lovely-Space/pull/111) の検証記録。本番の通信・巡回・通知・実サイトデータへの接続は保留し、ユーザーの許可なくマージしない。


### 利用者の追加確認：チャット送受信は未実施（2026-10-11）

利用者から、先の約88秒の通常画面計測中は**実際のチャットの送受信を行っていない**と明示的な報告を受けた。

したがって、この測定は**通常のMainActivityの表示・操作に伴うプロセスCPU/PSS観測**であり、チャットメッセージの送信・受信が生じた場合の性能・安定性を測ったものではない。前節のPSS範囲260.6〜348.9MiB、中央値297.9MiB、コア換算平均CPU約27.2%、モデル解放時のPSS減少（472.2→334.8MiB）という測定値に変更はないが、**チャット送受信中の測定値へ外挿してはならない**。

今後必要なのは、利用者が希望する場合に限り、通常のチャットを普段どおり操作した際の**同一プロセスの数値ログと操作感の確認**。本文・相手・部屋名・認証情報などを取得・送信する必要はない。現在のPoCはAIモデルを解放してから通常画面に移るため、チャット中のAI同時推論を評価する機能ではない。
